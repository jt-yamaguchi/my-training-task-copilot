## 3. API設計

### API一覧

| API ID | メソッド | パス            | 概要                                                             | 正常時 | 対応機能 |
| ------ | -------- | --------------- | ---------------------------------------------------------------- | ------ | -------- |
| A-01   | GET      | /api/tasks      | タスク一覧取得(完了日時を含む)。`sort=priority` 指定時は優先度順 | 200    | F-1, F-5 |
| A-02   | GET      | /api/tasks/{id} | タスク1件取得(完了日時を含む)                                    | 200    | —        |
| A-03   | POST     | /api/tasks      | タスク登録(優先度省略時は中、期限は任意)                         | 201    | F-2, F-5 |
| A-04   | PUT      | /api/tasks/{id} | タスク更新(完了切替・完了日時の自動記録/消去を含む)              | 200    | F-3      |
| A-05   | DELETE   | /api/tasks/{id} | タスク削除                                                       | 204    | F-4      |

### 入出力(共通)

- リクエスト(A-03): `{ "title": string, "description": string|null, "priority": "HIGH"|"MEDIUM"|"LOW", "dueDate": "YYYY-MM-DD"|null }` (`priority`省略時は`MEDIUM`、`dueDate`省略/null時は期限なし)
- リクエスト(A-04): `{ "title": string, "description": string|null, "done": boolean }`
- レスポンス: `{ "id": number, "title": string, "description": string|null, "priority": "HIGH"|"MEDIUM"|"LOW", "done": boolean, "dueDate": "YYYY-MM-DD"|null, "createdAt": string, "completedAt": string|null }`
- A-04で更新するのは既存どおりタイトル・説明・完了状態。作成時の期限は維持する
- `completedAt`はサーバー管理のオフセット付きISO 8601日時で、リクエスト項目には追加しない。未完了から完了にする更新の処理時点でUTCの現在日時を記録し、取り消すと`null`に戻す
- 完了状態のまま更新した場合は完了日時を保持し、取り消し後の再完了では新しい日時を記録する。登録直後は`null`
- 画面では`done=true`かつ`completedAt`が非nullの場合のみ、`Asia/Tokyo`固定で秒まで表示する(例: `完了日時: 2026/10/13 15:30:45`)
- 導入前の完了済みタスクは実際の完了日時が不明なため`null`を保持し、日時の表示を省略する
- 期限切れはクライアントで判定する(期限日がブラウザーの今日より前、かつ未完了)
- A-01の`sort`は省略時にID昇順、`priority`指定時にHIGH→MEDIUM→LOW。同一優先度内はID昇順
- エラー: `{ "message": string }` に統一。バリデーション違反=400、対象なし=404

各項目の型・必須・文字数などの詳細は Swagger UI(/api/docs)を正とする。

## 4. データ設計

### ER図

```mermaid
erDiagram
    tasks {
        bigint id PK "自動採番"
        varchar_100 title "タイトル(必須)"
        varchar_500 description "説明"
        varchar_6 priority "HIGH/MEDIUM/LOW"
        boolean done "完了フラグ"
        date due_date "期限(任意)"
        timestamptz created_at "登録日時"
        timestamptz completed_at "完了日時(任意)"
    }
```

カラムの詳細定義は [04\_詳細設計.md](./04_詳細設計.md) のテーブル定義書を参照。

## 5. 処理方式

- 完了切替・削除は楽観的な単純更新とし、同時編集の排他制御は行わない(同時利用10名規模のため。要件2.性能)
- 一覧はページングなしの全件取得とする(タスク件数は数百件規模を想定)
