## 1. テーブル定義書

### tasks(タスク)

| カラム       | 型                       | NULL | 既定値            | 説明                                                               |
| ------------ | ------------------------ | ---- | ----------------- | ------------------------------------------------------------------ |
| id           | BIGINT (IDENTITY)        | 不可 | 自動採番          | 主キー                                                             |
| title        | VARCHAR(100)             | 不可 | —                 | タイトル                                                           |
| description  | VARCHAR(500)             | 可   | —                 | 説明                                                               |
| done         | BOOLEAN                  | 不可 | FALSE             | 完了フラグ                                                         |
| priority     | VARCHAR(6)               | 不可 | MEDIUM            | 優先度(HIGH/MEDIUM/LOW)                                            |
| due_date     | DATE                     | 可   | —                 | 期限日                                                             |
| created_at   | TIMESTAMP WITH TIME ZONE | 不可 | CURRENT_TIMESTAMP | 登録日時                                                           |
| completed_at | TIMESTAMP WITH TIME ZONE | 可   | —                 | 完了日時。作成直後・取り消し後・導入前の日時不明な完了タスクはNULL |
| category_id  | BIGINT                   | 可   | —                 | categories.idへの外部キー。削除時はNULLに戻す                      |

- 優先度は `CHECK (priority IN ('HIGH', 'MEDIUM', 'LOW'))` で制約する
- 対応マイグレーション: `V1__create_tasks.sql`(初期定義)、`V2__insert_seed_tasks.sql`(初期データ)、`V3__add_task_priority.sql`(優先度追加)、`V4__add_task_due_date.sql`(期限追加)、`V5__add_task_completed_at.sql`(完了日時追加)
- `completed_at`はデフォルト値を設けず、導入前の完了済みデータもNULLのままにする。実際の完了日時を復元できないため、登録日時や移行日時による補完は行わない
- カテゴリの対応マイグレーション: `V6__add_task_categories.sql`。既存タスクの`category_id`はすべてNULLのままとする
- 外部キー: `fk_tasks_category`、`categories(id)`参照、`ON DELETE SET NULL`。タスク自体は削除しない
- インデックス: 主キー、`idx_tasks_category_id`(`category_id`)

### categories(カテゴリ)

| カラム | 型                | NULL | 既定値   | 説明                                       |
| ------ | ----------------- | ---- | -------- | ------------------------------------------ |
| id     | BIGINT (IDENTITY) | 不可 | 自動採番 | 主キー                                     |
| name   | VARCHAR(100)      | 不可 | —        | カテゴリ名。`uk_categories_name`で一意制約 |

- 対応マイグレーション: `V6__add_task_categories.sql`。IDは固定せず「仕事」「私用」「勉強」を順に初期登録する
- 初期データはFlywayによる一度限りの投入とし、利用者が削除したカテゴリを再起動時に再投入しない
- 名称の前後空白は入力時に除去する。大小文字・全半角の同一化はしない

## 2. バリデーション仕様

| 対象        | ルール                                                  | 実装箇所                                             |
| ----------- | ------------------------------------------------------- | ---------------------------------------------------- |
| title       | 必須(空白のみ不可)、100文字以内                         | TaskRequest(Bean Validation)                         |
| description | 500文字以内                                             | 同上                                                 |
| priority    | HIGH/MEDIUM/LOWのいずれか。省略時はMEDIUM               | TaskCreateRequest / DB制約                           |
| dueDate     | `YYYY-MM-DD`形式の日付。省略/nullの場合は期限なし       | TaskCreateRequest                                    |
| categoryId  | 任意の正整数。指定時は存在するカテゴリであること        | TaskCreateRequest / TaskService / DB外部キー         |
| name        | 前後空白除去後必須、100文字以内、同名不可               | CategoryCreateRequest / CategoryService / DB一意制約 |
| フロント側  | タイトル空の間は追加ボタン非活性、maxLengthで文字数制限 | TaskForm.tsx                                         |

## 3. 例外・トランザクション方針

- 対象が存在しない場合は Service で `NotFoundException` を送出し、`GlobalExceptionHandler` が404 + `{"message"}` に変換する
- バリデーション違反は同ハンドラが400 + `{"message"}` に変換する
- タスク作成・絞り込みで不正/存在しないカテゴリIDを指定した場合も400。カテゴリ削除の対象なしは404
- 同名カテゴリ登録は400。事前チェックに加えてDBの一意制約違反もカテゴリ作成時に400へ変換する
- トランザクション境界は Service(クラスに `@Transactional(readOnly = true)`、更新系メソッドに `@Transactional`)

## 4. シーケンス図

カテゴリ削除はDBの外部キー制約に委譲し、複雑なアプリ内の更新手順を持たないため、シーケンス図は省略する。
タスク保持・カテゴリ未設定化はTaskApiTest、カテゴリ管理はCategoryApiTest、画面の選択・絞り込み・削除後の状態はApp.test.tsxを振る舞いの正とする。
