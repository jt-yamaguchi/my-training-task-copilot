# 本番サーバーの掃除（次の課題への準備）

タスク管理アプリの課題が終わったら、**同じサーバーを次の課題（在庫管理）でも使います**。前の課題のものを消して、まっさらな状態に戻します。

## 消すもの・残すもの

| | 対象 |
|---|---|
| 消すもの | 前課題のコンテナ ／ DBのデータ ／ 全イメージ ／ compose設定ファイルと `.env` |
| 残すもの | スワップ・Docker Engine・certbotと証明書（OSの設定） ／ 静的IP・DNS（サーバーの外にあるもの） |

ドメインと証明書は次の課題でもそのまま使えます（DNS・証明書の作業は発生しません）。

## 手順

🟩 **サーバー（Lightsail）**

```bash
$ docker compose -f docker-compose.prod.yml down -v   # コンテナとDBデータ(ボリューム)を削除
$ docker system prune -af                             # 全イメージ・ビルドキャッシュを削除
$ rm -f docker-compose.prod.yml .env                  # 前課題の構成ファイルを削除
```

> `down -v` でDBのデータごと消えます。次の課題は別のスキーマをFlywayでゼロから作るためです。消えて困るデータは本番に置いていない、という前提が守られているかを意識してください。

## 確認

🟩 **サーバー（Lightsail）**

```bash
$ docker ps -a    # 何も表示されなければOK(コンテナなし)
$ docker images   # 何も表示されなければOK(イメージなし)
$ ls ~            # compose設定ファイルと .env が消えていることを確認
```

**完了条件**: コンテナ・イメージ・構成ファイルが空になっている（Docker本体と証明書はそのまま）

> サーバーの調子がおかしいまま次の課題に入りたくないときは、掃除ではなく**作り直し**（[server-rebuild.md](./server-rebuild.md)）を選んでください。素のOSから15〜30分で再現できます。

次の課題（在庫管理）の始め方は [repos-guide.md](./repos-guide.md) を参照してください。構成ファイルの配置と `.env` の作成（[prod-prepare.md](./prod-prepare.md) の手順3-3と同じ流れ）から再開します。
